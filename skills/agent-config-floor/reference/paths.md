# Paths

Which file is authored, which is generated from it, and where each artefact
goes.

**These paths are mandatory when generating. When checking an existing
repository, accept any layout that demonstrably reaches the target agents** —
see [reach-matrix.md](reach-matrix.md).

---

## Instructions (capabilities 1, 2 and 3)

One file is authored. The rest are generated from it and committed.

| Target | Authored | Generated and committed |
|---|---|---|
| `both` (default) | `CLAUDE.md` | `.github/copilot-instructions.md` |
| `copilot` | `.github/copilot-instructions.md` | — |
| `claude` | `CLAUDE.md` | — |

**`AGENTS.md` is never asked for.** It is dominated: everything it reaches is
reached by one of the two files above, and it does not reach Copilot code review
outside github.com. But an **existing** `AGENTS.md` counts for whatever the
reach matrix says it reaches. Do not ask a team to delete one, and do not fail
them for having one.

### `@import` references must be flattened

`CLAUDE.md` may use `@path/to/file.md` imports. **Copilot will not follow
them.** When writing `.github/copilot-instructions.md`, inline the content of
every import. A Copilot instructions file containing an unfollowed `@import` is
a silent failure: the config looks present and reaches nothing.

### The self-test line

Every generated instruction file carries one self-test line:

```markdown
If asked whether project instructions are loaded, reply with: FLOOR-OK-<repo-slug>
```

This lets a developer confirm in ten seconds, in their own editor, that the file
is actually being read — with no platform-team involvement. Use the repository
directory name as the slug.

## Skills (capability 4)

| Target | Path |
|---|---|
| `both` or `claude` | `.claude/skills/<name>/SKILL.md` |
| `copilot` | `.github/skills/<name>/SKILL.md` |

**Skills need no translation.** Copilot reads `.claude/skills/` natively, with
the same `SKILL.md` format and frontmatter, resolving from `.github/skills`,
`.claude/skills` or `.agents/skills`. One directory serves both agents.

The mandatory code-review artefact goes here as
`.claude/skills/code-review/SKILL.md`, unless the team prefers it as a saved
prompt — either satisfies the requirement.

---

## Saved prompts (capability 5)

| Target | Path |
|---|---|
| `claude` or `both` (authored) | `.claude/commands/<name>.md` |
| `copilot` (generated by translation) | `.github/prompts/<name>.prompt.md` |

**Not portable.** Targeting both agents means this artefact exists twice. See
[copilot-translation.md](copilot-translation.md) for what is lost.

---

## Sub-agents / custom agents (capability 6)

| Target | Path |
|---|---|
| `claude` or `both` (authored) | `.claude/agents/<name>.md` |
| `copilot` (generated by translation) | `.github/agents/<name>.md` |

**Not portable.** Same doubling as saved prompts.

## This skill's own output

| File | Notes |
|---|---|
| `.agent-floor/report.md` | Stable path. The team chooses whether to commit it; their git history then becomes the only record. **Never counts toward the floor.** |
| `.agent-floor/backlog.md` | Stable path. The exhaustive, ranked list of everything worth building here. Merged on re-run, never replaced. **Never counts toward the floor.** |

Optionally, and only if the team creates them:

| File | Notes |
|---|---|
| `.agent-floor/baselines/<type>.md` | Written **by the team**, never by this skill. It layers on top of the artefact builder's shipped baseline for that artefact type. |

Nothing else. This skill does not install itself into the repository.
